# 滑动窗口最大值

## 题目概述

给定整数数组 `nums` 和窗口大小 `k`，窗口从左到右每次移动一位，要求返回每个窗口内的最大值。

## 直接思路为什么会超时

一种直观做法是维护当前窗口中的所有元素，每次窗口形成后重新遍历窗口找最大值。

这种做法的问题在于：

- 每次求最大值都要遍历整个窗口，时间复杂度是 `O(k)`
- 如果使用顺序表删除窗口最左侧元素，头部删除通常也需要移动元素

整体时间复杂度接近 `O(n * k)`，当 `n` 和 `k` 较大时容易超时。

## 优化思路：单调队列

这道题的核心不是保存整个窗口，而是保存“可能成为最大值的下标”。

使用一个双端队列 `Deque<Integer>` 存储数组下标，并保持这些下标对应的值从队头到队尾单调递减。

这样可以保证：

- 队头始终是当前窗口最大值的下标
- 新元素进入时，可以淘汰掉所有比它小的元素
- 过期元素离开窗口时，可以从队头快速移除

## 队列中存的是什么

队列中存的是 **下标**，不是值。

这样设计有两个原因：

1. 需要通过下标判断元素是否已经滑出窗口
2. 需要通过 `nums[index]` 获取对应的值进行大小比较

例如：

```java
deque.offerLast(i);
```

这里入队的是 `i`，所以：

```java
deque.peekFirst()
```

取得的是下标，不是数组值。

## 核心代码

```java
class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        int n = nums.length;
        int[] ans = new int[n - k + 1];
        Deque<Integer> deque = new ArrayDeque<>();

        for (int i = 0; i < n; i++) {
            if (!deque.isEmpty() && deque.peekFirst() < i - k + 1) {
                deque.pollFirst();
            }

            while (!deque.isEmpty() && nums[deque.peekLast()] < nums[i]) {
                deque.pollLast();
            }

            deque.offerLast(i);

            if (i >= k - 1) {
                ans[i - k + 1] = nums[deque.peekFirst()];
            }
        }

        return ans;
    }
}
```

## 代码逻辑拆解

### 1. 移除过期下标

```java
if (!deque.isEmpty() && deque.peekFirst() < i - k + 1) {
    deque.pollFirst();
}
```

当前窗口范围是 `[i - k + 1, i]`。

如果队头下标小于左边界，说明它已经不在窗口内了，需要移除。

### 2. 维护单调递减队列

```java
while (!deque.isEmpty() && nums[deque.peekLast()] < nums[i]) {
    deque.pollLast();
}
```

如果新进入的元素比队尾对应的值更大，那么队尾元素以后不可能成为最大值，可以直接删除。

这一步会一直删除，直到队列重新满足单调递减。

### 3. 加入当前元素下标

```java
deque.offerLast(i);
```

当前下标进入队尾，作为新的候选者。

### 4. 记录窗口最大值

```java
if (i >= k - 1) {
    ans[i - k + 1] = nums[deque.peekFirst()];
}
```

当窗口大小达到 `k` 后，队头就是当前窗口最大值的下标。

## 为什么队列里不只存最大值下标

如果只保存当前最大值，一旦它滑出窗口，就必须重新遍历窗口寻找新的最大值，效率又会退化。

因此队列中不仅保存当前最大值，还保存一批按大小有序的候选下标：

- 队头：当前最大值
- 后续元素：未来可能成为最大值的候选者

## 复杂度分析

- 时间复杂度：`O(n)`
- 空间复杂度：`O(k)`

原因是每个元素最多只会：

- 进入队列一次
- 从队头或队尾移除一次

因此总操作次数与数组长度成线性关系。

## 和其他解法对比

### 1. 暴力解法

- 时间复杂度：`O(n * k)`
- 优点：思路直观
- 缺点：大数据下容易超时

### 2. 优先队列（堆）

- 时间复杂度：`O(n log k)`
- 优点：比暴力快，也容易理解
- 缺点：仍然不是最优

### 3. 单调队列

- 时间复杂度：`O(n)`
- 优点：这道题的标准最优解
- 缺点：初学时不如暴力法直观

## 适合理解这类题的总结

遇到滑动窗口题时，可以先问自己三个问题：

1. 元素进入窗口时，是否需要更新某种结构
2. 元素离开窗口时，是否需要快速删除
3. 是否可以避免每次都重新遍历整个窗口

如果题目要求的是窗口内的最值，通常就要考虑单调队列。

## 经验结论

“滑动窗口最大值”这题的关键，不是维护整个窗口，而是维护一个有序的候选最大值队列。

单调队列的本质是：

- 让最大值始终放在最前面
- 让没有竞争力的元素尽早出队
- 让每个元素只处理有限次，从而把复杂度降到 `O(n)`
