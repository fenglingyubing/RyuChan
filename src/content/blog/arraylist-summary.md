# Java 面试专项：ArrayList 扩容机制

> 参考来源：`ArrayList 源码分析  JavaGuide.md`
> 整理目标：围绕 `ArrayList` 扩容机制提炼高频面试题，适合背诵和口头表达。

---
### 【面试题】：`ArrayList` 的扩容机制是什么？
- **【核心答案】**：
  * `ArrayList` 底层是动态数组，容量不足时会触发扩容，本质是“创建更大的新数组并复制旧数据”。
  * JDK 8 中默认无参构造不会立刻分配容量，第一次添加元素时才会把容量扩到 `10`。
  * 后续扩容通常按旧容量的 `1.5` 倍增长，如果 `1.5` 倍仍小于本次所需最小容量，就直接扩到 `minCapacity`。
- **【原理解析】**：`add(E e)` 时会先调用 `ensureCapacityInternal(size + 1)`，再进入 `ensureExplicitCapacity(minCapacity)` 判断 `minCapacity - elementData.length > 0` 是否成立，成立才会走 `grow(minCapacity)`。`grow()` 里先算 `newCapacity = oldCapacity + (oldCapacity >> 1)`，也就是旧容量加一半；如果新容量还不够，就直接用 `minCapacity`；如果超过 `MAX_ARRAY_SIZE`，再通过 `hugeCapacity()` 做边界保护。最终通过 `Arrays.copyOf()` 申请新数组并复制旧元素。整个过程说明 `ArrayList` 的“动态”不是原地扩容，而是数组替换。
- **【面试扩展】**：扩容是有代价的，因为会触发数组复制，所以 `ArrayList` 尾插虽然均摊时间复杂度接近 `O(1)`，但单次扩容那次插入并不是严格 `O(1)`。如果业务能预估数据量，初始化时直接指定容量，或者提前调用 `ensureCapacity()`，都能减少扩容次数。
- **【一句话总结】**：`ArrayList` 的扩容本质就是容量不够时按 `1.5` 倍申请新数组并搬迁旧数据。

---
### 【面试题】：为什么 `ArrayList` 无参构造后不是立刻分配长度为 `10` 的数组？
- **【核心答案】**：
  * JDK 8 的无参构造只是让 `elementData` 指向一个共享空数组，并不会马上分配 `10` 个槽位。
  * 只有第一次真正执行 `add` 时，才会把容量初始化到默认值 `10`。
  * 这样做的目的，是避免大量空集合对象一创建就占用不必要的堆内存。
- **【原理解析】**：无参构造函数里，`elementData = DEFAULTCAPACITY_EMPTY_ELEMENTDATA`，它本质上是一个长度为 `0` 的共享空数组。执行 `add()` 时，`calculateCapacity(elementData, minCapacity)` 会先判断当前数组是不是这个默认空数组；如果是，就返回 `Math.max(DEFAULT_CAPACITY, minCapacity)`，也就是至少扩到 `10`。这说明 JDK 8 把“对象创建”和“数组真正分配”拆开了，属于典型的延迟初始化策略。JDK 6 则不同，无参构造时就直接创建长度为 `10` 的数组。
- **【面试扩展】**：这个点非常适合回答“JDK 6 和 JDK 8 的 `ArrayList` 初始化差异”。工程上它的价值主要体现在对象量很大但很多列表最终并不会存元素时，可以降低内存浪费。
- **【一句话总结】**：JDK 8 的 `ArrayList` 用延迟分配把“默认容量 10”推迟到了第一次插入时。

### 【面试题】：`ArrayList` 为什么通常按 `1.5` 倍扩容，而不是 `2` 倍？
- **【核心答案】**：
  * `1.5` 倍是扩容次数和空间浪费之间的折中方案。
  * 如果扩得太小，会频繁复制数组；如果扩得太大，会浪费更多堆内存。
  * 所以 `1.5` 倍不是绝对最优，而是通用场景下更平衡的工程选择。
- **【原理解析】**：扩容成本主要来自两部分，一是新数组分配，二是旧数组复制。如果每次只扩一点，插入稍多就会不断触发 `copyOf()`，吞吐下降；如果每次翻倍，虽然扩容次数少，但数组尾部空闲空间会更多，内存利用率下降，还可能加大 GC 压力。`ArrayList` 选择 `oldCapacity + (oldCapacity >> 1)`，本质是在 CPU 成本和内存成本之间做平衡。另外，右移一位相当于除以 `2`，是一个非常轻量的位运算实现。
- **【面试扩展】**：面试里如果被追问“那为什么 `HashMap` 是 2 倍，`ArrayList` 却是 1.5 倍”，可以答：两者设计目标不同。`HashMap` 扩容要配合哈希桶重新分布，容量通常保持 `2` 的幂；`ArrayList` 更关注顺序存储场景下的空间利用率和扩容频率平衡。
- **【一句话总结】**：`1.5` 倍扩容不是数学最优解，而是时间和空间之间的工程折中。

### 【面试题】：`ensureCapacity()` 有什么作用？实际开发中值不值得用？
- **【核心答案】**：
  * `ensureCapacity(int minCapacity)` 的作用是提前保证底层数组至少有这么大的容量。
  * 它可以减少后续 `add()` 过程中反复扩容和数组复制的次数。
  * 如果元素数量可预估，值得用；如果数据量很小或无法预估，收益通常不明显。
- **【原理解析】**：`ensureCapacity()` 本身不会直接往集合里放数据，它只是提前触发容量检查。如果当前容量不足，就走和正常扩容一样的逻辑。它的优化点在于把多次“小步扩容”压缩成一次“大步到位”的扩容，减少 `Arrays.copyOf()` 的调用次数。因为数组复制是一次真实的内存搬迁操作，所以当批量写入数据时，提前扩容通常能让性能更稳定。
- **【面试扩展】**：典型场景是批量导入、分页汇总、一次性加载大量查询结果，比如明确知道要装 `10000` 条数据，就可以先 `new ArrayList<>(10000)` 或调用 `ensureCapacity(10000)`。如果是普通业务接口里几十条数据的常规操作，不需要为了这点优化牺牲代码可读性。
- **【一句话总结】**：`ensureCapacity()` 的价值就是用一次预扩容换掉多次隐式扩容。

### 【面试题】：`ArrayList` 扩容时为什么常看到 `Arrays.copyOf()` 和 `System.arraycopy()`？
- **【核心答案】**：
  * `ArrayList` 扩容最终要做的是数组复制，所以这两个 API 都很关键。
  * `Arrays.copyOf()` 更像是“帮你创建新数组并完成复制”。
  * `System.arraycopy()` 更像是“把已有数组中的一段数据拷贝到目标数组指定位置”。
- **【原理解析】**：在 `grow()` 中，`ArrayList` 使用 `Arrays.copyOf(elementData, newCapacity)`，因为扩容场景下需要先创建一个更大的新数组，再把旧数组内容复制过去。而在 `add(int index, E element)`、`remove(int index)` 这类中间插入或删除场景下，更常见的是 `System.arraycopy()`，因为目标数组通常还是当前数组本身，只需要把指定区间整体后移或前移。进一步看源码，`Arrays.copyOf()` 内部本质上还是调用了 `System.arraycopy()`，只不过前者多了一层“创建新数组”的封装。
- **【面试扩展】**：这个点经常和“为什么 `ArrayList` 中间插入慢”一起问。标准回答就是：中间插入不仅可能触发扩容，还要触发区间元素搬移；而尾插通常只在容量不足时才有搬迁成本。
- **【一句话总结】**：`ArrayList` 的扩容和搬移都离不开数组复制，只是一个负责“新建并复制”，一个负责“按区间复制”。
