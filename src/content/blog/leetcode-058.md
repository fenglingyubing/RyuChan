# 78. 子集

## 题目要求

给你一个整数数组 `nums`，其中元素互不相同，要求返回它的所有子集。

也就是说，对于数组中的每个元素，我们都可以有两种选择：

- 选它
- 不选它

最后把所有可能情况都找出来。

例如：

```java
输入：nums = [1,2,3]
输出：[[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]
```

这里的 `[]` 也算一个子集，叫空集。

---

## 这道题的核心是什么

这题的核心是：

- 子集问题，本质上是在每个位置做“选 or 不选”的决策
- 只要把所有决策路径都走一遍，就能得到所有子集

因为题目要求的是“所有可能的子集”，所以这是一个非常典型的回溯题。

不过和“全排列”不同，这题不要求顺序，只要求从原数组里挑一些元素出来。

所以：

- 全排列关注的是“排列顺序”
- 子集关注的是“选哪些元素”

---

## 为什么子集问题适合回溯

假设：

```java
nums = [1,2,3]
```

对于数字 `1`：

- 可以选
- 可以不选

对于数字 `2`：

- 可以选
- 可以不选

对于数字 `3`：

- 可以选
- 可以不选

这样每个元素都有 2 种状态，所以总共会有：

- `2^n` 个子集

回溯正适合把这种“逐个元素做选择”的过程写出来。

---

## 标准解法：回溯

### 思路

我们用一个 `path` 表示当前已经选中的元素。

然后从某个起始位置 `start` 开始，依次尝试把后面的元素加入当前集合。

这道题有一个非常关键的点：

- 每到一个递归节点，当前的 `path` 本身就是一个合法子集

所以和全排列不同，子集题不是等到长度满足条件才加入答案，而是：

- 递归一进入，就先把当前 `path` 加入结果集

---

## Java 参考实现

```java
class Solution {
    private List<List<Integer>> result = new ArrayList<>();
    private List<Integer> path = new ArrayList<>();

    public List<List<Integer>> subsets(int[] nums) {
        backtrack(nums, 0);
        return result;
    }

    private void backtrack(int[] nums, int start) {
        result.add(new ArrayList<>(path));

        for (int i = start; i < nums.length; i++) {
            path.add(nums[i]);
            backtrack(nums, i + 1);
            path.remove(path.size() - 1);
        }
    }
}
```

---

## 代码逐段解析

### 1. 结果集和路径

```java
private List<List<Integer>> result = new ArrayList<>();
private List<Integer> path = new ArrayList<>();
```

- `result`：保存所有子集
- `path`：保存当前递归路径，也就是“当前这个子集里已经选了哪些元素”

例如：

- `path = []` 表示空集
- `path = [1]` 表示当前选了 `1`
- `path = [1,3]` 表示当前选了 `1` 和 `3`

---

### 2. 入口函数

```java
public List<List<Integer>> subsets(int[] nums) {
    backtrack(nums, 0);
    return result;
}
```

这里直接从下标 `0` 开始搜索。

`start` 的含义是：

- 下一次选元素时，只能从 `start` 及其后面的位置开始选

这样做的目的是避免重复。

比如：

- `[1,2]` 和 `[2,1]` 在子集问题里其实是同一个子集

所以我们只允许“按顺序往后选”，不回头选前面的元素。

---

### 3. 为什么一进入递归就加入结果

```java
result.add(new ArrayList<>(path));
```

这是这道题最关键的一句。

原因是：

- 当前的 `path` 本身就是一个合法子集
- 不管它有几个元素，都应该加入结果集

例如当递归走到：

- `[]`
- `[1]`
- `[1,2]`
- `[1,2,3]`

它们每一个都应该被收集起来。

这里同样必须拷贝：

```java
new ArrayList<>(path)
```

不能直接写：

```java
result.add(path)
```

因为 `path` 后面还会继续变化。

---

### 4. 枚举当前可以选择的元素

```java
for (int i = start; i < nums.length; i++) {
```

含义是：

- 从 `start` 开始，尝试把每个元素加入当前子集
- 每次加入一个元素后，再递归去找后续可能的组合

为什么要从 `start` 开始，而不是从 `0` 开始？

因为子集不关心顺序，只关心选了哪些数。

如果从 `0` 开始反复选，就会出现：

- 先选 `1` 再选 `2`
- 先选 `2` 再选 `1`

这样会产生重复子集。

而 `start` 能保证：

- 当前层之后只往后选
- 每个子集只生成一次

---

### 5. 做选择

```java
path.add(nums[i]);
```

表示：

- 把 `nums[i]` 加入当前子集

比如当前：

- `path = [1]`

如果现在选 `2`，就变成：

- `path = [1,2]`

---

### 6. 递归进入下一层

```java
backtrack(nums, i + 1);
```

这里传 `i + 1` 很重要。

意思是：

- 已经用了 `nums[i]`
- 后面只能从它后面的元素开始继续选

这样就保证：

- 一个元素不会被重复使用
- 不会产生顺序不同但内容相同的重复子集

---

### 7. 撤销选择

```java
path.remove(path.size() - 1);
```

这一步表示：

- 当前分支已经搜索完成
- 把刚刚加入的元素删除
- 恢复现场，继续尝试下一个元素

这就是回溯的固定模式：

```java
做选择
递归
撤销选择
```

## 用 `nums = [1,2,3]` 走一遍

初始状态：

```java
path = []
```

进入递归，先加入结果：

- `[]`

然后从下标 `0` 开始选：

### 选 `1`

- `path = [1]`
- 加入结果：`[1]`

再从 `1` 后面开始选。

#### 在 `[1]` 的基础上选 `2`

- `path = [1,2]`
- 加入结果：`[1,2]`

再从 `2` 后面开始选。

##### 在 `[1,2]` 的基础上选 `3`

- `path = [1,2,3]`
- 加入结果：`[1,2,3]`

然后回溯，删掉 `3`，回到 `[1,2]`。

`[1,2]` 后面没有别的元素了，再回溯删掉 `2`，回到 `[1]`。

#### 在 `[1]` 的基础上选 `3`

- `path = [1,3]`
- 加入结果：`[1,3]`

然后回溯，删掉 `3`，回到 `[1]`。

`[1]` 这一层结束，再回溯删掉 `1`，回到 `[]`。

### 选 `2`

- `path = [2]`
- 加入结果：`[2]`

接着选 `3`：

- `path = [2,3]`
- 加入结果：`[2,3]`

回溯后回到 `[]`。

### 选 `3`

- `path = [3]`
- 加入结果：`[3]`

最终结果就是：

```java
[[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]
```

顺序可以不同，但内容是一样的。

---

## 回溯树怎么理解

对于 `nums = [1,2,3]`，回溯树可以理解成：

```text
[]
|- [1]
|  |- [1,2]
|  |  |- [1,2,3]
|  |- [1,3]
|- [2]
|  |- [2,3]
|- [3]
```

这棵树里的每一个节点，都是一个子集。

这就是为什么我们一进入递归就要收集当前 `path`。

---

## 这道题和全排列的区别

很多人刚学回溯时，容易把“子集”和“全排列”写混。

它们的关键区别是：

### 全排列

- 每个位置都要选一个数
- 顺序重要
- 需要 `used[]` 标记元素是否使用过

### 子集

- 每个元素只有“选或不选”
- 顺序不重要
- 不需要 `used[]`
- 用 `start` 控制下一层从哪里开始选

所以这道题最关键的不是“一个数能不能重复使用”，而是“为了避免重复子集，只能往后选”。

---

## 时间复杂度

设数组长度为 `n`。

### 时间复杂度

- 一共有 `2^n` 个子集
- 每次加入结果时，拷贝当前路径最多需要 `O(n)`

所以总时间复杂度通常写作：

- `O(n * 2^n)`

### 空间复杂度

- 递归深度最多 `n`
- `path` 最多存 `n` 个元素

不计结果集时，额外空间复杂度为：

- `O(n)`

---

## 这道题最容易错的点

### 1. 忘记一开始就加入结果

如果你只在递归结束时才加入结果，就会漏掉很多中间子集。

因为：

- `[]` 是子集
- `[1]` 是子集
- `[1,2]` 也是子集

并不是只有走到底才算答案。

### 2. 忘记拷贝 `path`

错误写法：

```java
result.add(path);
```

正确写法：

```java
result.add(new ArrayList<>(path));
```

### 3. 递归时还从当前下标继续开始

如果写成：

```java
backtrack(nums, i);
```

就可能重复使用当前元素，逻辑会错。

正确的是：

```java
backtrack(nums, i + 1);
```

因为下一层应该从当前元素后面开始选。

---

## 一句话总结

这道题就是用回溯枚举每个元素“选或不选”的所有情况：递归过程中当前 `path` 本身就是一个合法子集，所以每次进入递归先收集答案，再从 `start` 开始向后尝试加入新元素，最后通过回溯恢复现场。
